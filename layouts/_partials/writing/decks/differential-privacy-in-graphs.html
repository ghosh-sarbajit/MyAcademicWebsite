Differential Privacy

6 / 38

Motivation

  • Consider a database, containing the private responses of 100 students on their habit of taking tea
  • Consider two queries in the database:
    • What is the total number of students who do take tea?
    • What is the total number of students (excluding row 58) who do take tea?
  • With answers to these queries, analysts can find the private response of the student of row 58
  • This motivates us to obfuscate answers, before releasing, them so that both answers look identical
  • How much noise to add?
7 / 38

Quantification of Noise

One such method proposed, for obfuscating the answer was by Dwork et. al.[4] 1. The steps are as follows:

  1. List out all possible datasets that differ in exactly one row (also called neighboring datasets)
  2. Evaluate both the query over all possible neighboring datasets
  3. Calculate the maximum difference evaluated over all possible pairs of neighboring datasets (also called the sensitivity of the query)
  4. Calibrate the answer to the query before releasing it by adding noise proportional to the sensitivity

This technique was coined as Differential Privacy by the authors

1Cynthia Dwork et al. "Calibrating noise to sensitivity in private data analysis". In: TCC 2006

Different Perturbation Methods

  • Noise is added to the answer before sending it to the analyst (Output perturbation)
  • Noise added to the data before computation (Input perturbation) [7]2
  • Another variation, in the domain of machine learning: Noise is added to the data at the time of computation (Gradient perturbation) [1]3

Neighboring Graphs

  • To apply differential privacy in graph data, we have to define neighboring datasets first
  • Two types of neighboring graphs are possible:
    • Two graphs that differ in exactly one edge
    • Two graphs that differ in exactly one node and in the edges that connect the particular node to the graph

Object of Differential Private Algorithms

Two Orthogonal Interests:

  • Utility
  • Privacy

Impossible to get both in the worst case

Objective: To find differentially private algorithms that:

  • Preserves privacy for all graphs
  • Retains a significant amount of accuracy for an inference about a subclass of graphs

    • They leverage the graph structure for learning and feature extraction
  • Key Concepts
    • Message Passing: GNNs use message passing to aggregate information from neighboring nodes
18 / 38

Detour: Message Passing in GNNs

  • Message Passing Concept
    • GNNs perform iterative message passing between nodes to update their features
    • Nodes exchange information with their neighbors
  • Message Aggregation
    • For each node, the messages from neighbors are aggregated to update its feature vector
    • This process is repeated for a fixed number of iterations
  • Node Update Function
    • The node update function combines the node's current feature with the aggregated messages to produce a new feature vector

Making GNNs Differentially Private

The work by Ameya Daigavane et al.[3]7 proposes a version of DP-SGD for private training of GNN. The method they followed was gradient perturbation. Brief discussion:

  • To train GNN draw multiple sample sub-graphs from the graph
  • Calculate the gradient of the error
  • Add Gaussian noise to the gradient
  • Update the new gradient

The authors showed that the algorithm proposed satisfies a relaxed version differentially privacy[9]8

Differential Privacy (Formal Definition)

Here we will define the formal definition of Differential Privacy. Let:

  • 𝒟: Dataset containing personal information
  • 𝒟′: Dataset after discarding one row from 𝒟 (Neighboring dataset to 𝒟 denoted by 𝒟∼𝒟′)
  • 𝒜: An algorithm that receives the query from the user, evaluates the query, and, sends the obfuscated answer to the user
  • 𝒬: Set of all possible queries
  • 𝒴: Set of all possible outputs of 𝒜
  • ϵ: Privacy budget

Now the algorithm 𝒜 will be called a Differentially Private algorithm, with privacy budget ϵ if,

|log⁡[Pr[𝒜(𝒟,q)=y]Pr[𝒜(𝒟′,q)=y]]|≤ϵ,∀y∈𝒴,∀q∈𝒬,∀𝒟∼𝒟′

Relaxation Of Differential Privacy

Two relaxations of differential privacy have been proposed.

  • Approximate Differential Privacy
    • One additional parameter is introduced over Differential Privacy to capture the failure probability of the private mechanism; and tried to optimize it [5]10
    • Criterion: Pr[𝒜(𝒟,q)=y]≤eϵPr[𝒜(𝒟′,q)=y]+δ
  • Renyi Differential Privacy
    • This relaxation tries to address the above issue but with different parameterization Differential Privacy [9]11
    • Criterion: Pr[𝒜(𝒟,q)=y]≤(eϵPr[𝒜(𝒟′,q)=y])1−1α

𝔼[ℒ(θT)−ℒ(θ*)]=𝒪(‖𝒞‖Glog⁡TT)
